# Development notes

## Version 1.1.0

Scope: retain the user's native WordPress tile layout and name-display controls while simplifying the supported content interfaces to shortcodes and Gutenberg. Removed Divi/Elementor adapters, module metadata, editor bundles and integration-specific build tools/tests. Existing builder widgets/modules must be replaced with shortcodes or Gutenberg blocks; no automatic content conversion is performed.

The shared Client Credentials token requests exactly `section:programme:read section:event:read section:member:read section:member:write` by default, preserving the user's API change. Legacy optional scope arguments reuse that same token if the scope is already included. Removed the separate Authorization Code/PKCE connection and all runtime dependencies on its saved tokens. Credential changes/reset also delete legacy connection options.

Waiting-list availability follows the saved destination. Clear waiting list is protected by administrator capability and its own nonce, deletes only the destination and disables render, credential preparation, submission and direct API writes. Signed tokens remain bound to the destination; replay/rate guards and partial-write handling remain intact. A privacy-policy URL is optional; the acknowledgement links to it when present, otherwise explicitly explains transfer to OSM.

Settings now use Configuration; old privacy/public-data/advanced-options bookmarks remain aliases. The original detailed application-creation instructions are restored with all four requested scopes listed from the API source. General retains the user's shortcode documentation placement. Legal privacy-policy terminology and legacy option/action names remain compatible.

Verification uses offline HTTP fixtures and an isolated WordPress installation, never production data or real applications. See plugin-check-results.md for the current release verification. Live OSM account permissions and real API responses still require staging validation.

The unreleased work is consolidated into 1.1.0, following the published 1.0.0. General section tiles use three columns on wide screens, two on medium screens and one on phones and contain independent programme/event and Section Points rows. Old generic website-display and duplicated patrol-selection controls are removed. Section IDs, current terms and Reset configuration are always visible.

Per-section configuration uses `osm_section_points_settings[section_id]` with firstname/lastname modes and excluded member IDs. Existing global name modes remain a compatibility fallback; edits affect only the selected section. The administrator roster API checks manage_options before any request and returns only active youth member names and IDs from accessible sections, including unassigned members. The roster is request-local. Checkbox exclusions are combined with explicitly retained missing-member IDs; outages never silently erase exclusions. Public adapters filter excluded IDs before formatting, fail closed for unidentified members whenever exclusions exist, and return neither raw members nor IDs. The shared renderer applies the same policy to shortcodes and Gutenberg. Existing shortcode/block identifiers remain supported with the new visible Section Points label.

UI follow-up: replaced obsolete layout selectors with a scoped native WordPress tile stylesheet and explicit spacing. Configuration and Authentication now use their full single-column container instead of leaving an empty right column. Admin CSS/JS versions use filemtime so keeping release 1.1.0 does not trap browsers on stale assets. Removed the unused hosted waiting-list template/URL validator and empty frontend JavaScript file; legacy public identifiers and action aliases remain compatible.

Each Section Points form has a client-side Preview row using only its already loaded administrator roster. Names, patrol labels and exclusion selections render through text nodes (never innerHTML), following the PHP full/initial/hidden rules; unsaved changes never call OSM or mutate public configuration. The roster supplies first/last/patrol labels in addition to its existing identity fields for this purpose, without persistence.

OSM quota observations are recorded from complete validated X-RateLimit headers before HTTP status validation, including 429 errors. Only numeric limit/remaining/reset/report timestamps are stored in the non-autoloaded osm_api_usage option. Used is derived from limit minus remaining; reset headers are relative seconds. Missing/invalid headers keep the last valid snapshot. Quota survives cache purges; credential changes clear it with rollback on failed authentication, and configuration reset removes it. The admin countdown uses a monotonic browser clock and stops at an awaiting-response state; no polling consumes extra quota.

Waiting-list contact fix: member creation succeeds independently from the adult write. The adult update now uses the observed custom-data bulk-update route with section_id in the query, associated_type=member, associated_is_section=false, confirmed associated_id and group_id=1. The previous member-contact route did not save the adult details in the reported account. The supported custom-data response uses status=true; malformed/negative responses still produce an honest partial-result state, without retrying member creation. References: https://raw.githubusercontent.com/newcastlescouts/osm-api-docs/main/openapi.yaml (custom-data update). The user's real account still requires a staging submission to confirm its permissions and field behavior. Do not resubmit an application whose child was already created; its adult details must be completed on that existing OSM record.

The default waiting-list design is now a scoped, responsive card with grouped fieldsets, inherited typography, accessible focus/disabled states and editable CSS variables. The Configuration tile and README document these hooks. No CSS framework, dependency, stored custom CSS or extra settings surface is required. Both frontend style registration paths use filemtime to invalidate old CSS without changing 1.1.0.

Application follow-up: date of birth is requested as independent day/month/year numeric text fields. Server validation checks required parts, digit lengths, checkdate, allowed year range and future dates before normalising to ISO. Legacy ISO inputs are accepted only when no new part fields are supplied. New fields retain escaped request-local values on errors.

Fork research (jonbloor/osm-for-wordpress feature/waiting-list-form) found optional parent_note sent via OSM Helper to a mapped Notes field. This plugin retains direct writes. Optional parent_note is capped at 2,000 Unicode characters; willing_to_help is an optional allowlisted choice (yes/no/discuss). Notes and the labelled helping answer are appended to one identifiable text Notes column discovered through getData for the confirmed new member, using updateColumn with returned group/column IDs. Missing, ambiguous or failed mapping produces a distinct partial exception after child/adult creation. No retry creates another child, and no application data is persisted or logged.

OSM_Notifications resolves selected WordPress user IDs at send time and calls wp_mail once per unique current email address. Explicitly selected users receive only a fixed summary/link, including partial-save warnings, never applicant fields. No notification is sent before confirmed child creation or on duplicate POST. Exceptions/negative mail results do not change application success; only counts/time are saved for the Configuration tile. Existing administrator capability/nonce boundaries protect recipient changes; configuration reset clears recipients and delivery status. Tests intercept all mail; browser verification uses an isolated pre_wp_mail fixture, never a real mail transport.

Plugin identity renamed to Online Scout Manager (slug/package/text domain online-scout-manager), retaining version 1.1.0. The main file is online-scout-manager.php and release ZIPs contain a matching online-scout-manager/ folder. Saved osm_* options, action hooks, existing shortcode/block identifiers and PHP compatibility names remain intact. GitHub repository and fork links retain their real existing URLs; no remote repository was renamed. Because the plugin installation path changes, deactivate the old plugin before activating the renamed package; WordPress does not identify it as an in-place update of the old plugin file.
